# Портфолио Дениса Волошина

Сайт: https://denisvoloshin.ru. GitHub Pages публикует ветку `main`.

## Обновление

Данные проектов, фотографии и SEO хранятся в `src/content.json`, общий HTML — в `src/template.html`. После изменения выполните из корня репозитория:

```sh
node scripts/build.cjs
```

В коммит должны попасть исходники, все сгенерированные `index.html` (включая папки отдельных кадров внутри проектов) и `assets/content.js`. Сборка не требует сторонних пакетов. Общие стили и поведение находятся в `assets/site.css` и `assets/site.js`. `assets/metadata.js` используется и сборкой, и браузером: он задаёт одинаковые адреса, заголовки и превью.

## Фотографии

- `url` — существующий файл Tilda CDN для слайд-шоу и полноразмерного просмотра.
- `id` — постоянный идентификатор кадра. Не изменяйте его при перестановке фотографий или замене URL: опубликованные ссылки используют этот ID.
- `width` и `height` — исходные пропорции фотографии.
- `thumb` — путь без суффикса к двум JPEG в `assets/thumbs`: `-400.jpg` и `-800.jpg`. Они должны сохранять пропорции, без дополнительной обрезки. Текущее качество JPEG — 88.

Новые кадры получают новый уникальный ID. Начальные ID получены из первых 12 символов SHA-256 исходного URL с префиксом `p-`. При добавлении фотографии обновляйте также список изображений в `sitemap.xml`.

## Ссылки и «Поделиться»

Пример: `/vglubine/p-d672b884660d/`. Адрес открывает существующий поп-ап, а стрелки обновляют кадр без перезагрузки. Закрытие возвращает к миниатюрам. Кнопка «Поделиться» использует системное меню, если браузер его поддерживает; иначе копирует ссылку. При запрете буфера обмена появляется окно с адресом для ручного копирования. Отмена системного меню ничего не копирует.

Для каждого кадра сборка создаёт настоящий HTML-файл с собственными canonical, `og:url`, `og:image`, Twitter Card и ImageObject. Превью использует соответствующий JPEG шириной 800 пикселей на том же домене; исходная фотография в поп-апе остаётся на Tilda CDN. Мессенджер получает метаданные сразу в HTTP-ответе, без выполнения JavaScript. Оформление карточки и обрезку изображения выбирает сам мессенджер.

Прежние адреса `?photo=…#mini` поддерживаются и заменяются в браузере на новый путь. Для индивидуального превью следует копировать новую ссылку через «Поделиться»: GitHub Pages отдаёт одинаковый HTML для разных query-параметров, поэтому у старого формата остаётся общее превью проекта. Уже отправленные карточки могут оставаться в кэше мессенджера.

Статический HTML содержит ссылки, описания и миниатюры до запуска JavaScript. При обычной работе используется прежний интерфейс; без JavaScript доступна запасная статическая галерея.

## Админка и автоматическое добавление

Закрытая панель: https://voloshin-photo-admin.dualgear.chatgpt.site. Её исходники хранятся отдельно в репозитории Site; публичный интерфейс портфолио не зависит от админки. Вход в панель — через ChatGPT, доступ оставлен владельцу.

Процесс `.github/workflows/add-photo.yml` принимает проект, прямой HTTPS URL, необязательный alt и UUID запроса. Запускать его может только `voloshindenis` в ветке `main`. Для серверного секрета панели `GITHUB_ACTIONS_TOKEN` используется fine-grained token только для этого репозитория с Actions: read/write. Ключ нельзя хранить в этом репозитории или в клиентском коде.

Обработка выполняется в GitHub Actions: скачивание до 40 МБ, проверка формата и размеров, учёт EXIF-поворота, две миниатюры JPEG, постоянный ID, данные галереи, HTML кадров и sitemap. Новый ID зависит от проекта и содержимого файла; менять его после публикации нельзя. Исходник остаётся по введённому адресу. Для новых фотографий сохраняется SHA-256, чтобы обнаруживать копии под другим URL.

Для описания кадра используется `alt`, при отсутствии — название проекта и номер кадра. Изменение alt не меняет визуальный дизайн. Миниатюры хранятся без дополнительных обрезок и без EXIF, в sRGB.

Проверки выполняются до единого коммита. После push процесс явно запрашивает сборку GitHub Pages (публикация из `main`, корень `/`) и проверяет доступность кадра с его метаданными. Отдельный запрос сборки нужен, поскольку push от `GITHUB_TOKEN` сам по себе не запускает Pages. При сбое push не перезаписывает параллельные изменения; запрос можно повторить. Режим `dry_run` проверяет импорт и сборку, не делает commit/push и не публикует сайт.

Локальная проверка: `npm ci`, `npm test`, `npm run build`, `node scripts/check-site.cjs`. Переменные для ручного импорта: `PHOTO_PROJECT`, `PHOTO_URL`, `PHOTO_ALT`; затем `npm run import-photo`. `sitemap.xml` теперь обновляется сборкой автоматически, включая отдельные страницы кадров.
